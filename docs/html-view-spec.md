# TickTick 可视化 · HTML 视图内容规格

> ⚠ **早期设计稿**。权威 schema / 渲染契约以各平台 `references/visualization-reference.md` 为准（与本规格已分叉，不再双份维护）。

这份文档只定义**每个页面要展示什么内容**（区块、字段、数据来源），作为 HTML 设计依据。
视觉风格 / 布局细节由设计决定。

---

## 总览：两个页面

| 页面 | 目的 | 一句话 |
|---|---|---|
| **A. 看板** | 操作性视图——所有未完成任务按「截止紧迫度」分布 | 「我现在该先做什么、哪里堵塞」 |
| **B. 周报** | 回顾性视图——本周完成情况 + 下周展望 | 「这周做了什么、下周要做什么」 |

---

## 共享约定（两页都适用）

### 数据注入方式
agent 拼好一个 JSON，写入页面里的占位：
```html
<script>const DATA = { /* 见下文 schema */ };</script>
```
页面是纯前端，只读这个 `DATA` 渲染。不调网络、不写回 TickTick。

### 视觉约定（建议，可改）
- **优先级配色**：高(5)=红 · 中(3)=橙 · 低(1)=蓝 · 无(0)=灰
- **项目色**：直接用 TickTick 项目自带的 `color` 字段
- **时间**：全部本地时区（Asia/Shanghai），ISO 8601 带偏移，如 `2026-07-14T23:59:00+0800`
- **只读快照**：页面本身不改任务；要改 → 回对话里说（"把 X 推迟到周五"）→ agent 调 MCP → 再"刷新"重生成页面
- **空状态**：每个区块数据为空时显示一句"暂无"，不留大白块
- **截断提示**：任一列表超过 100 条，只渲染前 100 条并在底部注明"显示前 100 条，共 N 条"（不静默截断）

### 共用数据 Schema
两页共用一个大 JSON，各自取需要的字段：

```jsonc
{
  "generatedAt": "2026-07-14T17:30:00+0800",  // 页面生成时刻
  "user": "StoneLL1",                          // 显示名（可选）

  "stats": {                                   // 顶部 KPI 用
    "total": 42,                               // 全部未完成
    "overdue": 3,                              // 过期未完成
    "today": 7,                                // 今日到期
    "thisWeek": 15                             // 本周(含今天起7天)到期
  },

  "tasks": [                                   // 任务全集（看板用；扁平数组，页面自行分桶）
    {
      "id": "task-id",
      "title": "写季度报告",
      "projectId": "prj-1",
      "projectName": "工作",
      "projectColor": "#F2994A",
      "priority": 5,                           // 0/1/3/5
      "dueDate": "2026-07-14T23:59:00+0800",   // 可为 null（无截止日）
      "startDate": null,
      "tags": ["紧急"],
      "content": "摘要正文…",                   // 可为空
      "column": "今日"                         // agent 预先分好的桶（仅看板页用）
    }
  ],

  "report": {                                  // 仅周报页用
    "rangeStart": "2026-07-07T00:00:00+0800",  // 本周一
    "rangeEnd":   "2026-07-13T23:59:59+0800",  // 本周日（回顾截止）
    "completed":  [ /* 本周完成的任务，结构同 tasks[]，多一个 completedAt */ ],
    "upcoming":   [ /* 下周到期的未完成任务 */ ],
    "overdue":    [ /* 目前已过期仍未完成的 */ ],
    "byDay": [                                // 完成趋势（本周一~今天，每天一格）
      { "date": "2026-07-07", "completed": 3 }
    ],
    "byProject": [                            // 本周完成按项目归并
      { "name": "工作", "count": 5, "color": "#F2994A" }
    ]
  }
}
```

## 页面 A · 看板（Kanban）

**目的**：一眼看清未完成任务按截止紧迫度分布，定位「该先做什么」「哪里堆积」。

### 顶栏
- 标题：`任务看板`
- 副信息：生成时间 `2026-07-14 17:30`
- KPI 卡片（4 个）：`全部 N` · `过期 N` · `今日 N` · `本周 N`（取 `stats`）
- 列维度切换器：`截止日 / 优先级 / 项目`（默认「截止日」）

### 主体 · 列（默认「截止日」分桶，共 6 列）
| 列名 | 包含 |
|---|---|
| 过期 | dueDate < 今天 00:00 |
| 今日 | dueDate 落在今天 |
| 明日 | dueDate 落在明天 |
| 本周 | dueDate 落在本周三~周日（今日/明日之后、7 天内） |
| 之后 | dueDate 在 7 天之后 |
| 无日期 | dueDate 为 null |

> 列名带计数徽标，如 `今日 (7)`。

### 切换到「优先级」维度
列变成：`高 · 中 · 低 · 无`（按 5/3/1/0）。

### 切换到「项目」维度
每个项目一列；「无项目/收件箱」单独一列。

### 卡片内容（每张卡）
- **标题**（主）
- **项目色标**：左侧 3px 竖条，颜色 = `projectColor`
- **优先级圆点**：右上角小圆，颜色按优先级
- **截止时间**：如 `今天 23:59` / `周五` / `7/20`；无日期则不显示
- **标签**：小 chip，如 `紧急`
- **点击展开**（只读）：显示 `content` 全文 + 项目名 + 完整截止时间

### 数据来源
- `filter_tasks(filter={"status":[0]})` —— 一次拉全部未完成
- agent 端按 dueDate 分好桶，填入每条 task 的 `column` 字段；页面只负责渲染

### 空状态
- 整页无任务：`🎉 没有未完成任务`
- 单列为空：列保留，显示 `—`

### 布局意图（轻描述）
- 顶栏一行；KPI 卡横排；列横向滚动（6 列在窄屏放不下），每列内部纵向滚动
- 卡片间距紧凑、信息密度偏高（看板本质是"扫"）

## 页面 B · 周报（Weekly Report）

**目的**：一周回顾 + 下周展望，适合周五/周末看，或定时生成。

### 时间范围
- **回顾**：本周一 00:00 ~ 今天 23:59（或本周日，看生成时机）
- **展望**：明天 ~ 下周日（未来 7~14 天）

### 顶栏
- 标题：`周报 · 2026-07-07 ~ 2026-07-13`
- KPI 卡片（4 个）：
  - `本周完成 N`
  - `完成率 X%`（本周完成 / (本周完成 + 当前未完成)，或简单用 完成/计划）
  - `当前积压 N`（全部未完成数）
  - `过期未办 N`

### 区块 1 · 本周完成趋势
- 本周一~今天，每天完成量的小柱状图（mini bar）
- 一眼看哪天产出高、周末是否塌陷
- 数据：`report.byDay`

### 区块 2 · 本周完成清单
- 按项目分组列出 `report.completed`
- 每条：标题 · 项目色标 · 优先级圆点 · 完成时间（如 `周二 14:30`）
- 数据：`report.completed`

### 区块 3 · 下周到期的
- `report.upcoming`，按日期升序，同日按优先级降序
- 每条：标题 · 截止日 · 项目色标 · 优先级圆点
- 作用：提前知道下周哪几天压力大

### 区块 4 · 过期未办（需处理）
- `report.overdue`
- 高亮（红色基调），提醒尽快处理或重新排期
- 每条带「过期天数」（今天 − dueDate）

### 区块 5（可选）· 按项目分布
- `report.byProject`：本周完成在各项目的数量
- 可做成简单的横向条形（项目名 + 条 + 数字）

### 数据来源
- 本周完成：`list_completed_tasks_by_date(search={"startDate": 本周一, "endDate": 今天})`
- 下周到期：`list_undone_tasks_by_date(search={"startDate": 明天, "endDate": 下周日})`
- 过期未办：`filter_tasks` 拉 `status=[0]` 后筛 dueDate < 今天
- 完成率/积压：同一次 `filter_tasks(status=[0])` 算总数

### 空状态
- 本周无完成：`本周还没有完成的任务`
- 下周无到期：`下周暂无到期任务`（正面语气）
- 无过期：区块整块省略或显示 `✓ 没有过期任务`

### 布局意图（轻描述）
- 顶栏 + KPI 一行；趋势图一条；下面完成清单与下周到期**双栏**（桌面）/ 上下堆叠（窄屏）
- 阅读密度低于看板（周报是"读"不是"扫"），留白多一点

## 数据来源对照表

| 页面/区块 | MCP 调用 | 备注 |
|---|---|---|
| 看板 · 全量任务 | `filter_tasks(filter={"status":[0]})` | 一次拉全，agent 端分桶 |
| 看板 · KPI | 同上（计数） | 不额外请求 |
| 周报 · 本周完成 | `list_completed_tasks_by_date` | 范围本周一~今天 |
| 周报 · 下周到期 | `list_undone_tasks_by_date` | 范围明天~下周日（≤14天 OK） |
| 周报 · 过期/积压 | `filter_tasks(filter={"status":[0]})` | 复用全量再筛 |

## 已知缺口 / 注意点

1. **「本周新增」拿不到**：MCP 任务对象不暴露创建时间，所以周报**不做"本周新增 N"**指标；只用"完成"和"到期"。
2. **`list_undone_tasks_by_date` 上限 14 天**：下周展望没问题；若想看更远需改用 `filter_tasks` 全量再筛。
3. **大数据量**：单页任务很多时，看板每列封顶 100 + 注明总数；周报完成清单同理。
4. **日期解析**：所有中文相对日期（本周一、下周日）由 agent 在生成时换算成绝对 ISO 时间注入 JSON，页面只显示绝对/友好格式，不自己算"本周"。
